# Minor Fixes — Business Discovery API

لطفاً مخزن فعلی `ARVIN-B/business-discovery` را بررسی و اصلاحات زیر را با حداقل تغییر در کد اعمال کن.

هدف این کار، اصلاح چند ایراد جزئی در نسخه فعلی است؛ بنابراین از بازنویسی معماری، تغییر رفتارهای تأییدشده یا اضافه کردن قابلیت‌های جدید خودداری کن.

## 1. اصلاح نرمال‌سازی شماره موبایل

در تابع `normalize_mobile` فایل `app/main.py` یک ایراد وجود دارد.

در حال حاضر بعضی از شماره‌هایی که پیش‌شماره کشور `+98` دارند و بعد از آن صفر ابتدایی شماره داخلی نیز نوشته شده، درست نرمال‌سازی نمی‌شوند.

تمام فرمت‌های معتبر زیر باید به یک شماره استاندارد تبدیل شوند:

```text
09123456789
9123456789
+989123456789
+98 912 345 6789
+98 09123456789
+98 0912 345 6789
00989123456789
0098 0912 345 6789
989123456789
98 09123456789
0912-345-6789
0912 345 6789
0912.345.6789
0912(345)6789
۰۹۱۲۳۴۵۶۷۸۹
٠٩١٢٣٤٥٦٧٨٩
```

همه موارد معتبر باید به این فرمت تبدیل شوند:

`09xxxxxxxxx`

الزامات:

- ارقام فارسی و عربی پشتیبانی شوند.
- پیش‌شماره‌های `+98`، `0098` و `98` به‌درستی حذف شوند.
- وجود صفر ابتدایی بعد از پیش‌شماره کشور نیز پشتیبانی شود.
- جداکننده‌هایی مانند فاصله، خط تیره، نقطه و پرانتز مدیریت شوند.
- شماره ناقص یا نامعتبر پذیرفته نشود.
- شماره تلفن ثابت همچنان کاملاً نادیده گرفته شود.
- Regex استخراج شماره نیز با منطق نرمال‌سازی هماهنگ باشد تا فرمت‌های جدید فقط در تابع نرمال‌سازی پشتیبانی نشوند، بلکه واقعاً از متن صفحات استخراج شوند.

برای تمام حالت‌های بالا تست واحد اضافه کن.

## 2. اصلاح مدیریت خطاهای SearXNG

در تابع `search_sites` فایل `app/main.py`، مدیریت خطا باید اصلاح شود.

در نسخه فعلی، تشخیص خطای SearXNG به وجود دامنه‌های قبلاً پردازش‌شده وابسته شده است. در نتیجه ممکن است خطای واقعی SearXNG در دور دوم یا سوم به‌اشتباه مانند خالی بودن نتایج تفسیر شود.

رفتار مورد انتظار:

1. پاسخ موفق SearXNG با `results: []` به معنی جست‌وجوی موفق بدون نتیجه است.
2. خطای HTTP، خطای اتصال، Timeout یا پاسخ JSON نامعتبر باید به‌عنوان خطای واقعی ثبت شود.
3. وجود `excluded_domains` نباید باعث مخفی شدن خطای SearXNG شود.
4. خطای دور اول باید به‌عنوان خطای سرویس جست‌وجو گزارش شود و نباید به‌صورت موفقیت با نتایج خالی نمایش داده شود.
5. اگر دور دوم یا سوم با خطا مواجه شد، نتایجی که در دورهای قبلی به دست آمده‌اند حفظ شوند.
6. در صورت خطای دور دوم یا سوم، ادامه جست‌وجو متوقف شود و خطا در Log و اطلاعات هشدار پاسخ نهایی قابل تشخیص باشد.
7. خطای واقعی جست‌وجو نباید با حالتی که SearXNG سالم است ولی نتیجه‌ای پیدا نمی‌کند اشتباه گرفته شود.

در صورت نیاز می‌توانی ساختار داخلی مدیریت خطا را کمی اصلاح کنی، اما ساختار اصلی API و پاسخ‌های موفق فعلی را بی‌دلیل تغییر نده.

برای این موارد تست واحد بنویس:
- خطای SearXNG در دور اول.
- خطای SearXNG در دور دوم، در حالی که دور اول نتیجه داشته است.
- خطای SearXNG در دور سوم.
- پاسخ موفق با نتایج خالی.
- پاسخ موفق با نتایج غیرخالی.

## 3. حفظ رفتار Deduplication شماره‌ها

این رفتار از قبل مشخص شده و باید دقیقاً حفظ شود:

- هر شماره موبایل استاندارد در کل پاسخ فقط یک‌بار ثبت شود.
- اگر یک شماره در چند صفحه یا چند وب‌سایت مختلف پیدا شد، فقط اولین مورد ثبت شود.
- شماره تکراری نباید زیر وب‌سایت دیگری دوباره وارد خروجی شود.
- `source_url` اولین مورد ثبت‌شده حفظ شود.
- اگر یک وب‌سایت فقط شماره‌هایی داشته باشد که قبلاً در وب‌سایت‌های دیگر ثبت شده‌اند، نباید به‌عنوان یک وب‌سایت موفق جدید شمرده شود.
- هر وب‌سایت فقط زمانی یک مورد موفق محسوب شود که حداقل یک شماره موبایل جدید و یکتا به خروجی اضافه کند.

تست موجود `test_duplicate_phone_across_websites_is_only_returned_once` را حفظ کن و در صورت نیاز کامل‌تر کن.

**این منطق را تغییر نده.**

## 4. تکمیل `.gitignore`

فایل `.gitignore` را برای یک پروژه Python/FastAPI به شکل کامل و استاندارد اصلاح کن.

حداقل موارد زیر باید نادیده گرفته شوند:

```gitignore
# Python cache
__pycache__/
*.py[cod]
*$py.class

# Virtual environments
.venv/
venv/
env/
ENV/

# Environment and secrets
.env
.env.*
!.env.example

# Test and coverage
.pytest_cache/
.coverage
.coverage.*
htmlcov/
.tox/
.nox/

# Build and distribution
build/
dist/
*.egg-info/

# IDE
.idea/
.vscode/
*.swp
*.swo

# OS
.DS_Store
Thumbs.db
```

اگر فایل‌های موقت یا cache دیگری مختص همین پروژه وجود دارند، موارد مناسب را نیز اضافه کن.

نکات مهم:

- `.env.example` نباید نادیده گرفته شود.
- فایل `.env` و اطلاعات محرمانه نباید وارد Git شوند.
- فایل‌های `__pycache__` و `*.pyc` که قبلاً وارد Git شده‌اند را از Git tracking خارج کن تا دیگر در مخزن نمایش داده نشوند.
- برای این کار از `git rm --cached` استفاده کن تا فایل‌های محلی موردنیاز سرویس بدون ضرورت حذف نشوند.
- فایل‌های سورس، تست‌ها و مستندات نباید تحت تأثیر این پاک‌سازی قرار بگیرند.

## 5. تست و بررسی نهایی

پس از اصلاحات:

1. تست‌های واحد موجود را اجرا کن.
2. تست‌های جدید مربوط به فرمت شماره‌ها را اجرا کن.
3. تست‌های جدید مربوط به مدیریت خطاهای SearXNG را اجرا کن.
4. تست Deduplication بین چند وب‌سایت را اجرا کن.
5. تست زنده با SearXNG و Firecrawl واقعی را اجرا کن.
6. ساختار JSON پاسخ را بررسی کن.
7. بررسی کن که هیچ شماره تکراری در خروجی وجود نداشته باشد.
8. مطمئن شو هر شماره دارای `source_url` معتبر است.
9. بررسی کن که شماره‌های ثابت همچنان استخراج نمی‌شوند.
10. Health check سرویس و احراز هویت Bearer را بررسی کن.

توجه: تست زنده حتی اگر هیچ شماره‌ای پیدا نکند، در صورتی که سرویس سالم باشد، جست‌وجو و Crawl با موفقیت انجام شده باشند و پاسخ معتبر برگردد، می‌تواند موفق محسوب شود. پیدا نشدن شماره موبایل به‌تنهایی خطا نیست.

## 6. محدودیت تغییرات

این درخواست صرفاً برای اصلاح موارد بالا است.

موارد زیر را تغییر نده:

- معماری اصلی سرویس
- الگوریتم سه دور جست‌وجو و ضریب ۱.۶
- منطق فعلی Deduplication سراسری شماره‌ها
- تعداد صفحات و عمق Crawl
- تنظیمات Firecrawl
- تنظیمات SearXNG
- Docker و کانتینرهای موجود
- Nginx و تنظیمات شبکه
- Evolution API
- Chabokan
- API Key و سایر اطلاعات محرمانه

هیچ سرویس موجودی را حذف، نصب مجدد یا بازسازی نکن.

در صورت نیاز به Restart سرویس `business-discovery`، فقط همین سرویس را Restart کن.

## 7. گزارش نهایی الزامی

در پایان، گزارشی دقیق اما مختصر ارائه بده که شامل موارد زیر باشد:

1. فایل‌های تغییرکرده و علت تغییر هرکدام.
2. پوشه‌های اصلی که در آن‌ها تغییر انجام شده است.
3. تست‌های اجراشده و تعداد تست‌های موفق و ناموفق.
4. نتیجه تست زنده با SearXNG و Firecrawl.
5. وضعیت نهایی سرویس و Health check.
6. تأیید اینکه سرویس‌های دیگر و زیرساخت موجود تغییر نکرده‌اند.
7. دستور دقیق اجرای تست‌های واحد و تست زنده.

**هیچ تستی را بدون اجرای واقعی موفق اعلام نکن و هیچ تغییری خارج از محدوده این درخواست انجام نده.**
